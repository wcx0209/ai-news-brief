NVIDIA/auto-ontology: A Python framework for building semantic, graph-based reasoning layers

Detailed Features Auto Ontology acts as a bridge between your raw databases and AI agents. It automatically ingests database schemas, profiles columns, and infers table relationships to build a semantic graph of your enterprise data. Developers can use it to translate natural language questions into accurate SQL queries powered by NVIDIA NIM, ensuring that every answer comes with verifiable provenance and execution steps. System Architecture The project is designed with a modern microservices architecture. It includes a Next.js frontend for the Web UI, a FastAPI Python backend for chat and catalog management, an ingestion worker for vector embeddings, and a PostgreSQL database equipped with pgvector to store both application data and the semantic ontology. Installation and Usage Getting started is straightforward using Docker Compose. You simply need to clone the repository, configure your environment variables including your NVIDIA API key in a .env file, and run Docker Compose to spin up the local stack. Once running, you can connect your databases and start asking questions through the built-in chat interface or integrate it with other tools via the MCP server.

Supernodes Move to Scale Delivery as AI Computing Enters a New Infrastructure Race

The Shift from Scale-out to Scale-up Traditional AI training used thousands of scattered GPUs connected via standard networks, causing massive communication delays and high idle rates. Supernodes use a Scale-up architecture to pack hundreds of cards into a single rack or pod, using high-speed interconnects like NVLink, Lingqu, or optical links to achieve ultra-low latency and unified memory addressing. The Battle for Interconnect Standards Whoever defines the interconnect protocol wins the industry. Tech giants like Nvidia, Huawei, and Alibaba are rolling out proprietary architectures to control the future of data centers. Meanwhile, modular pre-integrated designs are slashing deployment times from months to just two weeks, driving a massive boom in liquid cooling, high-speed connectors, and custom switching chips. Domestic Strategies and Future Challenges Chinese manufacturers are using supernode architecture to compensate for advanced manufacturing gaps, turning system-level integration into a competitive moat. However, scaling up past thousands of cards still poses software and hardware hurdles, making interconnect efficiency the ultimate ceiling for the next generation of AI infrastructure.

vercel-labs/agent-desktop: Computer use CLI for AI agents

Overview agent-desktop is a command-line interface and C library designed to give AI agents native computer-use capabilities. Instead of relying on brittle screenshots or pixel-matching techniques, it leverages official OS accessibility APIs to read desktop applications directly, presenting them as structured JSON trees. How It Works The tool inspects the target application and assigns a unique reference (ref) to every interactive UI element. The calling agent queries a snapshot, performs actions like clicking or typing using the ref, and checks the updated UI state in a continuous loop. By default, it operates headless, interacting with UI elements without needing to move the mouse pointer or steal active focus. Ecosystem and Integration agent-desktop natively supports macOS, Windows, and Linux by wrapping platform-specific accessibility APIs like AX API, UI Automation, and AT-SPI. It also includes an MCP (Model Context Protocol) server mode out of the box, allowing developers to easily expose all desktop commands as tools to any compatible AI assistant.

What Is Eval-Driven Development? How to Improve AI Agents

When building AI agents, developers often struggle to know if a recent change actually improved the system. Eval-driven development borrows from traditional test-driven development to solve this unpredictability. The process has three main steps: defining success clearly, writing evaluations before building, and comparing experiments iteratively. First, you create a short specification of what the agent should and shouldn't do. Next, you build a dataset of test cases, often using real user runs or synthetic data, and create evaluators using code or LLMs. Finally, you run a baseline, make your changes, and compare the side-by-side results to catch regressions and prevent overfitting.

How skills and agents work in AWS Quick

Core Concepts AWS Quick places an AI agent at the center, which follows instructions, loads required skills, and interacts with connected data sources like knowledge bases and dashboards. By default, every user has access to Quick, but teams can also configure custom agents for specific tasks such as HR onboarding. Working with Skills A skill in AWS Quick is a reusable set of instructions based on an open standard, acting like a folder with a Markdown file and optional scripts. Quick uses system skills for common tasks like generating documents or browsing the web, while allowing users to create, publish and share their own custom skills. Best Practices Building production-ready skills requires engineering best practices. Creators must plan for potential failures, test every change, and avoid hardcoded values to ensure skills work seamlessly across different environments and team members.
